# 마이페이지와 기억 반응

2026-10-25

## 화면 흐름

상단 계정 메뉴에서 중복된 내 기억 링크를 제거했다. 하단 내 기억은 현재 MapLibre와 호환 지도 인스턴스·카메라를 유지하고 `PersonalSpacePanel`을 연다. 처음에는 내 기록만 지도에 표시한다. 북마크·좋아요 체크박스는 선택한 집합을 합쳐 표시하며 중복 기억은 한 번만 나타난다. 모두 끄면 지도 조각도 숨겨진다.

패널을 닫으면 개인 지도 선택이 유지된다. 하단 지도를 누르면 공개 기억으로 돌아가고, 탐색은 공개 목록을 연다. 개인 공간은 내 정보·기록 수·저장 목록·연도/감정/공개 범위 필터·지도 모드·추천으로 구성된다. 상세에서 수정·삭제·사진·뒤로가기를 유지한다. `/my-map` 직접 주소와 기존 조정 메뉴도 이 개인 공간에 연결된다.

로그인 전에는 이동 없이 안내 패널을 연다. 로그인 버튼을 누르면 기존 인증을 사용한다. Sites는 서버 계정, GitHub Pages는 기존 브라우저 시연 세션이다. Pages 로그인은 실제 다중 사용자 인증이 아니다.

## 데이터와 개인정보

- `memory_reactions`: 기억·사용자·종류(like/bookmark) 복합 기본키로 중복 반응을 방지한다. 조회용 사용자·종류·시각 index가 있다.
- `memory_views`: 기억·익명화한 조회자 키가 복합 기본키다. 로그인 사용자는 계정, 비로그인 사용자는 탭 세션 UUID를 서버에서 SHA-256으로 처리한다. IP·이메일·원본 계정 ID를 조회 레코드에 저장하지 않는다. 이 수치는 엄밀한 고유 방문자 수나 부정 조회 방지 시스템이 아니다.
- `drizzle/0001_memory_activity.sql`과 Drizzle schema/snapshot을 추가했다. `pnpm db:migrate`가 기존 schema와 추가 migration을 적용한다. 기존 실서비스 DB는 같은 `CREATE IF NOT EXISTS` schema를 서버에서 초기화해 이전 자료를 보존한다.
- 공개 지도와 마커 DTO에 반응 수를 추가하지 않았다. 개별 상세보기가 열릴 때만 별도 API에서 조회·표시한다. 여러 기억을 펼친 장소 미리보기에는 반응 정보를 표시하거나 조회를 기록하지 않는다. 북마크 총수와 누가 반응했는지는 공개하지 않는다.
- private/unlisted는 작성자만 읽는다. 타인의 비공개 전환·삭제된 기억은 저장 목록·지도·개인 집계·추천에서도 제외한다. 기억의 존재와 반응 수를 비인가 사용자에게 전달하지 않는다. 익명 작성자의 식별자와 원본 좌표 보호를 유지한다.
- 개인 지도 bounds는 소유자의 정확한 좌표, 타인의 보호된 공개 좌표로 검사한다. 한 화면에 최대 200개, 각 개인 목록은 최대 40개를 반환한다. 한도는 UI에 안내한다. 개인화 응답은 `private, no-store`다.
- Pages는 IndexedDB v4의 별도 activity store를 사용한다. 기존 기억·사진·편집한 예시와 v3 자료는 보존한다. 반응·조회는 그 브라우저에만 저장되며 서버와 동기화하지 않는다.

## 추천

내 기록과 같은 장소·감정이 있는 다른 작성자의 공개 기억을 먼저 제안한다. 각 카드에 제안 이유를 표시한다. 기록이 없으면 울산의 공개 기억을 제안한다. 좋아요·조회수 기반 인기 순위, 다른 사용자의 비공개 정보, 외부 추천 서비스는 사용하지 않는다.

## API와 검증

- `GET/POST /api/memories/:id/activity`: 읽기 권한 확인 뒤 반응 요약·명시적 설정/취소·중복 조회 방지. 좋아요/북마크는 로그인 필수, 변경은 same-origin 검사와 Zod 검증을 거친다.
- `GET /api/users/me/space`: 로그인 필수. bounds·개인 지도 선택·기존 필터를 서버에서 적용한다.
- `node scripts/verify-personal-service.mjs http://localhost:5197`: localhost에서만 임시 검사 기억을 만들고 정리한다. 실제 D1에서 반응/조회 중복 방지, 로그인 경계, 근사 좌표, 추천, 비공개 전환 후 목록·집계·반응 접근 차단을 확인한다. 운영 DB를 검사 데이터로 수정하지 않는다.
- Playwright는 데스크톱/모바일 Chromium·WebKit에서 지도 인스턴스와 카메라 유지, 개인 목록/필터/추천, 기존 주소, 반응 설정·취소, 사진 CRUD·장문·뒤로가기를 확인한다.

실서비스의 실제 계정 로그인 완료 후 개인 공간을 사용하는 과정은 계정 인증이 가능한 브라우저에서 별도 확인이 필요하다. 로컬 인증 및 Pages 시연 세션으로 기능을 검사하고, 배포 사이트에서는 비로그인 경계와 공개 API를 확인한다.

## 검사 결과

`pnpm check` 통과(타입 검사·단위 11개·Worker 및 Pages 빌드), 마지막 lint는 경고 없이 통과했다. 사진 CRUD·장문·기존 탐색을 포함한 40개 검사는 40/40 통과했다. 이후 마지막 코드에서 개인 공간·기존 주소·지도 유지·테마·조정·개발자 진입·CRUD 검사 32개를 재실행해 32/32 통과했다. 전체 테스트 모음 전부를 한 번에 통과했다고 보고하지 않는다.

검사에서 발견한 포스트잇 반응 버튼의 pointer-events와 Safari hash 경로의 초기 패널 갱신을 수정했다. 패널 진입 중 위치 측정은 애니메이션이 멈출 때까지 기다리도록 검사 준비를 보완했고 겹침 기준은 유지했다. 로컬 실제 D1 API 검사도 통과했다. 생산 계정의 로그인 완료 이후 개인 공간은 이번 환경에서 검증하지 못했다.
