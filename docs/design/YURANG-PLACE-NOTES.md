# 장소의 기억을 포스트잇으로 펼치기

작성일: 2026-10-22 · 브랜치: `redesign/yeoun-2`

## 변경

한 장의 미리보기와 별도 장소 목록으로 나뉘던 UI를 `PlaceNoteBoard`로 합쳤다. `이곳의 이야기 N편`으로 묶는 중간 버튼과 미리보기 X를 제거했다. 장소 조회 응답의 각 기록을 제목·날짜·감정·본문 일부·익명 여부·첫 사진(있는 경우)을 가진 포스트잇으로 바로 보여 준다.

종이 배경만 최대 ±2.2° 회전한다. 카드의 글자와 조작 영역에는 회전을 적용하지 않는다. 위치는 각 축 ±8px 이내로 엇갈리고 종이 모서리와 그림자가 조금씩 겹친다. 열 때 생성한 seed는 로딩·스크롤·부모 재렌더 중 고정하며 같은 장소라도 새로 열면 다시 생성한다. 애니메이션은 이동과 불투명도만 사용하고 reduced-motion을 존중한다.

빈 지도 클릭/탭은 장소 보드만 닫는다. 작성은 CTA의 위치 선택으로만 시작한다. 드래그는 지도 탐색이며 닫기 트리거로 추가하지 않았다. 기존 MapLibre 클릭 구분을 사용해 gesture/lifecycle/크기 보정/카메라 제약을 건드리지 않는다. 보드가 지도 이벤트를 가로채는 전체 화면 backdrop을 만들지 않는다. 카드와 헤더만 포인터를 받고 빈 공간은 실제 지도에 통과시킨다.

Escape로도 닫으며 닫은 뒤 원래 지도 마커로 초점을 복귀한다. 상세로 이동할 때는 layout effect로 먼저 초점을 넘겨 이전 보드의 초점 정리가 상세의 키보드 처리를 빼앗지 않게 했다. 거리뷰 모달에서 Escape를 사용할 때 뒤의 보드를 함께 닫지 않는다.

데스크톱 세 열, 모바일 두 열(360px 이하 한 열)로 배치하며 긴 목록은 보드 안에서 스크롤한다. 하단 공통 내비게이션과 상단 헤더는 유지하며 모바일의 겹칠 수 있는 지도 조정/확대 컨트롤은 보드를 닫으면 복귀한다. 헤더의 지도에서 보기·거리뷰, 각 카드의 직접 상세 이동, 상세 뒤로가기·같은 장소 이전/다음·다른 기억 읽기는 보존했다.

## 데이터 경계

UI와 표시 상태만 변경했다. 공개 장소 조회 반경 100m, 최대 30건과 `hasMore` 계약은 그대로다. 30건을 초과하는 장소의 무제한 일괄 조회나 새로운 pagination API를 추가하지 않았다. 이 경우 전체 건수와 현재 표시 수를 안내한다. private/unlisted 제외, anonymous/approximate projection, 인증, 사진 저장 및 저장소는 변경하지 않았다. 가상의 울산 기록으로 테스트하며 실제 사용자 기록을 생성·수정·삭제하지 않는다.

## 검증

- 새 장소 포스트잇 검사 **12/12 통과**: Chromium/WebKit × 1440×900 데스크톱·390×844 모바일. 기억 5장 직접 표시, X/중간 펼치기 제거, 글자 수평·종이 회전 ±2.2° 이하, 열림별 배치 변경·스크롤 중 고정, 마지막 카드 접근, 실제 모바일 빈 지도 탭·Escape 닫기, 상세 왕복·거리뷰·지도 이동·reduced-motion을 확인했다.
- 전체 90개 실행에서 **89개 통과**. 나머지 1개는 기존 내 기억 경로의 URL이 바뀐 직후 아직 이전 메뉴가 교체되는 순간 위치를 읽어 null이 된 테스트 타이밍 문제였다. owner 화면 고유 메뉴가 보일 때까지 기다리도록 보완하고 해당 동작을 네 프로젝트에서 **4/4 재통과**했다. 위치 동일성·전체 메뉴·작성 진입에 대한 기존 assertion은 유지했다. 미해결 실패는 없다.
- `pnpm check`의 lint·typecheck·단위 테스트 10개·Worker/Pages 빌드 통과. 테스트 대기 조건 보완 후 lint·typecheck도 재통과했다. 기존 bundle 크기 경고와 framework route 분류 안내만 남는다.
- 실제 캡처를 확인해 카드 글자가 수평이고 제목·본문·footer가 다른 카드에 가리지 않는지, 모바일 마지막 카드가 스크롤로 도달 가능한지 확인했다. 캡처는 `place-notes/desktop.png`, `desktop-reopened.png`, `mobile.png`, `mobile-scrolled.png`에 보관한다.
- 초기 테스트에서 발견한 모바일 거리뷰 아이콘의 접근성 이름 누락과 보드/상세 간 초점 전환 문제는 코드 수정 후 같은 시나리오에서 재검증했다.
- 실물 iPhone/iPad Safari와 외부 Worker의 실제 로그인·DB 연결은 별도 실행하지 않았다. 브라우저 검증은 Pages production build이며 Worker는 빌드 검증했다. 지도 SDK·카메라·raster fallback·기억 좌표·API/저장소는 수정하지 않았다.
