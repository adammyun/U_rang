# 마이페이지와 이야기 목록 보완

2026-10-30 · `redesign/yeoun-2`

## 화면 구성

- 마이페이지의 기억 항목은 **내 기록 / 북마크 / 좋아요** 세 개다.
- 프로필의 ‘이름의 기억 보관함’ 옆에 **추천 기억**과 **숨은 이야기** 버튼을 둔다. 기존 하단 추천 링크는 제거했다.
- 버튼을 누르면 같은 모달의 제목과 내부 전체가 해당 목록으로 전환된다. 프로필·체크박스·설정·세 탭은 이 화면에서 숨긴다.
- 뒤로가기 또는 Escape는 마이페이지로 돌아간다. 이전 기억 탭·체크박스·지도 중심/확대를 유지한다. 상세에서 뒤로가면 출발한 추천 목록으로 돌아간다.
- X는 목록을 닫고 지도에 현재 목록의 위치를 남긴다. 하단 지도 버튼은 모두의 지도로 돌아간다.
- 기존 폭 540px의 80%인 432px을 데스크톱 기준으로 사용한다. 모바일은 화면 너비의 80%로 좌우 여백을 동일하게 둔다. 기존 하단 내비게이션·CTA는 유지한다.

## 지도 연결

추천 화면은 기존 개인 공간 API가 반환한 공개 추천 최대 8개만 같은 지도 overlay에 표시한다. 기본 내 기억/북마크/좋아요 선택 상태를 덮어쓰지 않으며 뒤로가면 기존 조합을 복원한다.

발견한 이야기 화면은 본인의 보관 기록에 있는 이야기 위치만 표시한다. 이 화면에서만 확대 임계값을 해제해 이미 발견한 위치를 다시 찾게 한다. 아직 발견하지 않은 장소나 기억 조각을 섞지 않는다.

화면 전환 시 기존 MapLibre의 `fitBounds`로 목록 범위를 맞춘다. 데스크톱은 왼쪽 모달과 하단 내비게이션을 피하는 여백을 적용한다. 목록 hover/focus는 지도 조각·이야기 표식에도 같은 강조를 적용하고, 지도 hover/focus도 목록에 연결한다. 화면 밖 위치에 목록 초점이 가면 해당 위치를 보여준다. 매번 전체 지도를 다시 만들거나 새로운 지도 레이어를 생성하지 않는다.

작은 모바일 화면에서는 기존 울산 카메라 범위를 유지하면서 멀리 떨어진 모든 장소를 동시에 담을 수 없는 경우가 있다. 현재 화면의 위치만 그리며 목록 초점 이동, 상세의 ‘지도에서 보기’, X로 목록 닫기를 통해 확인한다. 이 제한 때문에 지도 범위·현재 위치 정책·최소 확대 제한을 변경하지 않았다.

## 아이콘과 스타일

흐트러진 선형 장식 대신 기존 오픈소스 Lucide `BookOpenText`의 정돈된 책 윤곽을 공유한다. 지도 흔적, 숨은 이야기 버튼, 읽기 화면, 보관 카드가 같은 아이콘을 사용한다. 기본 지도에서는 희미하게, 발견 목록과 hover/focus에서는 산호색으로 선명하게 보인다.

기존 graphite/coral, Noto Sans KR, 종이와 테이프 토큰을 사용한다. 목록 화면은 짧은 fade/이동으로 전환하고 reduced-motion에서 효과를 제거한다. 44px 이상 선택 영역, 긴 제목 줄바꿈, 내부 스크롤, 모달 이름·뒤로가기 이름과 초점 복귀를 유지한다.

## 데이터·인증 경계

DB schema, migration, 서버 API·추천 산정·사진 접근·인증은 변경하지 않았다. 기존 사용자별 발견 보관함과 추천 DTO를 재사용한다. 추천은 public만, private/unlisted·익명 작성자·대략적 좌표의 서버 보호는 그대로다. UI 필터가 접근 권한을 대신하지 않는다.

## 검증 시나리오

기존 테스트의 추천/발견 탭 selector를 새 진입 버튼·목록 region으로 변경했다. 숨겨진 프로필 콘텐츠를 잘못 찾지 않도록 화면별 selector 범위를 한정했으며 assertion을 제거하지 않았다.

새 테스트는 정확히 세 탭, 432px/80vw 너비, 추천에만 해당하는 지도 조각, 목록→지도 강조, 추천 상세→추천 목록→기존 탭/필터/카메라 복원, 같은 지도 인스턴스 유지, 발견한 위치만 표시, 이야기 읽기 후 목록 복귀와 화면 가로 넘침을 확인한다. 모바일의 떨어진 장소는 전체 동시 표시 대신 초점을 둔 발견 위치 표시와 다른 미발견 위치가 섞이지 않는지 확인한다.

서버 게스트 로그아웃 검사는 실제 페이지 이동과 새 지도의 초기 로딩을 기다린 뒤 다음 동작을 하도록 고쳤다. 모바일에서 숨기는 상단 로그인 링크는 DOM 존재로 확인한다. 이야기 검사에서도 최초 지도 로딩 후 로그인으로 이동해 WebKit이 취소된 이전 요청을 오류로 기록하는 타이밍을 피한다. 잠깐 사라지는 게스트 라벨만으로 페이지 이동 완료를 판단하던 타이밍 문제이며 로그인 경계 assertion은 유지한다.

## 최종 검증

- `pnpm check`: lint, typecheck, 단위 **27/27**, Worker/Pages build 성공.
- Pages Playwright: 새 화면·지도 연동 8건, 기존 개인 공간 12건, 이야기 8건 = **28/28**.
- 서버 Playwright: 게스트 작성·사진·개인 설정·삭제·로그아웃 4건, 이야기 보관·재조회 4건 = **8/8**.
- Chromium/WebKit, 데스크톱 1440×900 / 모바일 390×844에서 캡처를 직접 검토했다.
- 축소된 모달의 체크박스는 짧은 표시명으로 한 줄에 배치하고 접근성 이름은 기존 전체 명칭을 유지했다.
- 초기 실패에서 상세 왕복 시 선택한 탭이 초기화되는 문제를 확인해 탭 상태를 부모로 옮겼다. 이후 기존 탭·필터·지도 카메라 복원 검사를 통과했다.
- 넓은 목록은 내부 스크롤, 빈 목록·로그인 안내, 키보드 초점, 페이지 가로 넘침을 확인했다. 새 패키지·DB migration·지도 제공자 변경은 없다.
- 기존 큰 JS 번들 경고는 남아 있다.
