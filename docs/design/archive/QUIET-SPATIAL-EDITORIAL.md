# Quiet Spatial Editorial — Design DNA

적용 기준: 실제 메인 화면의 `app/spatial-live.css`와 `components/memory-app.tsx` · 2026-10-13

이 문서는 **다른 프로젝트에 옮길 수 있는 디자인 언어**와 **여운에만 해당하는 제품 규칙**을 구분한다. 색과 배치를 그대로 복사하기보다 콘텐츠·공간·조작 사이의 우선순위를 재사용한다.

## 디자인 철학 — 범용

공간 또는 핵심 콘텐츠가 화면의 주인공이다. 인터페이스는 필요한 순간에 나타나고, 사용자가 이야기를 읽을 때는 뒤로 물러난다. 첫 화면에서는 목적과 첫 행동을 짧은 문장으로 알려 주고, 목록은 사용자가 탐색을 요청했을 때 연다. 기본 상태에서 대형 대시보드나 영구 목록을 두지 않는다.

**Quiet Spatial Editorial**은 조용한 공간 배경, 글을 읽는 듯한 정보 위계, 맥락에 따라 나타나는 조작을 뜻한다. Apple Spatial Memory는 이 프로젝트의 표현 방향이지 다른 프로젝트에서 Apple 제품 모양을 그대로 복제하라는 규칙이 아니다.

## 색상 시스템 — 범용 토큰

| 역할 | 현재 구현값 | 사용 원칙 |
| --- | --- | --- |
| `ink` | `#24352f` | 본문과 제목의 기본색 |
| `deep` | `#153e32` | 주요 행동, 선택 상태 |
| `muted` | `#64756c` | 설명과 메타 정보 |
| `surface` | `#f8f9f5` | 읽는 패널의 불투명 배경 |
| `canvas` | `#e6ece7` | 지도 로딩·빈 배경 |
| `accent` | `#ad6a5f` | 위치 흔적과 작고 따뜻한 강조 |
| `line` | `rgba(40,66,54,.13)` | 약한 구분선 |
| `focus` | `#b5574c` | 키보드 초점 윤곽 |

색은 의미 역할로 사용한다. 선택·초점·위험·감정이 색 하나에만 의존하지 않도록 형태와 텍스트를 함께 둔다. `accent`는 탐색의 흔적에 제한하고 큰 면적의 CTA는 `deep`을 쓴다.

## 타이포그래피 — 범용

- Editorial 제목: `Noto Serif KR` → `Batang` → `Georgia` 폴백. 굵기는 중간, 줄 간격은 넉넉하게 둔다.
- UI·본문: 한국어 시스템 sans-serif 폴백을 사용한다. 외부 글꼴이 실패해도 핵심 정보가 읽혀야 한다.
- 영문 eyebrow: 10–12px, 넓은 자간, 짧은 문구에만 사용한다.
- 본문은 장문 읽기에 맞게 1.7 이상의 줄 간격을 쓰고, 긴 문자열은 줄바꿈한다.
- 숫자·날짜·감정은 제목보다 약하게 표현한다. 정보가 없는 경우 가짜 값을 채우지 않는다.

## 레이아웃·여백·그리드 — 범용

기본 화면은 핵심 공간을 전체 viewport에 놓는다. 검색은 상단 중앙, 작은 내비게이션은 하단 중앙, 보조 도구는 가장자리에 둔다. 패널은 대상 콘텐츠의 맥락에서 열리며 나머지 화면을 불필요하게 덮지 않는다. 간격은 4/8/12/16/20/24/32px 계열을 우선하고 읽기 패널 안쪽은 화면 크기에 맞춰 20–40px을 준다. 카드보다 콘텐츠 사이 여백으로 위계를 만든다. 새 프로젝트에서는 콘텐츠 밀도에 맞게 수치를 조정하되 역할 관계를 유지한다.

## 버튼·카드·Floating UI — 범용

- 주 행동은 진한 녹색의 채워진 버튼, 보조 행동은 약한 표면과 선, 아이콘 행동은 접근 가능한 이름을 갖는 작은 원형 또는 둥근 사각형을 사용한다.
- 패널은 불투명한 종이색 표면으로 장문 가독성을 확보한다. 카드에는 얕은 경계와 절제된 그림자를 사용한다.
- 지도 위의 검색·메뉴·조작에만 선택적으로 Liquid Glass를 쓴다. 투명도만으로 패널을 구분하지 않고 밝은 경계와 배경색을 함께 둔다.
- 흐림은 약 20px 이하로 제한하고 `prefers-reduced-transparency`에서는 불투명 표면으로 전환한다.
- 모든 행동에는 hover, active, focus-visible, disabled 상태가 있어야 한다. 손가락 조작 대상은 44×44px 이상을 목표로 한다.

## 인터랙션·애니메이션 — 범용

공간의 대상을 고르면 작은 미리보기가 먼저 나타나고 콘텐츠를 고르면 읽기 패널로 확장된다. 움직임은 이 단계 관계를 설명할 때만 쓴다. hover·선택 전환은 약 160–220ms, 패널 진입은 약 300ms 범위로 제한한다. `prefers-reduced-motion`에서는 이동·반복 효과를 끈다. 오버레이에는 닫기 또는 뒤로가기 경로를 항상 둔다.

## 반응형·접근성 — 범용

데스크톱의 맥락 패널은 공간 위 한쪽에 놓고 모바일은 하단 시트로 전환한다. 데스크톱 레이아웃을 단순 축소하지 않는다. 모바일 하단 메뉴와 safe area, 가상 키보드, 긴 본문, 여러 사진을 포함한 내부 스크롤을 검증한다. 스크린리더가 패널을 식별할 수 있도록 이름과 제목을 주고 키보드로 패널을 닫을 수 있게 한다. 공간과 상호작용하지 못하는 사용자를 위해 텍스트 목록 탐색 경로를 남긴다.

## 재사용 가능한 구성 요소 — 범용

`FloatingSearch`, `FloatingNavigation`, `ContextPreview`, `EditorialDetail`, `ExplorePanel`은 다른 프로젝트에도 옮길 수 있는 **역할**이다. 각 구성 요소는 데이터를 직접 소유하지 않고 부모가 전달한 항목·상태·행동을 표현한다. 실제 구현은 제품의 기존 컴포넌트와 API를 재사용하고 하나의 화면만을 위해 거대한 범용 추상화를 만들지 않는다.

## 여운 프로젝트 전용 규칙

- 기본 지도는 울산을 중심으로 한 MapLibre 전체 화면이다. MapLibre lifecycle, 크기 보정, raster compatibility layer, attribution, 단일 marker overlay를 유지한다.
- 공개 viewport 조회에는 public 기억만 포함한다. private/unlisted 존재 여부와 approximate의 원좌표를 공개 UI·응답에 노출하지 않는다.
- 장소 마커 → 장소 미리보기 → 같은 장소의 여러 기억 → 개별 상세 순서를 유지한다. 가상 시안 데이터는 실제 앱에서 사용하지 않는다.
- `기억 남기기`는 지도 위치 선택 후 기존 작성 폼을 연다. 내 기억 관리, 사진, 필터, 거리뷰 연결은 기존 기능을 이용한다.
- Worker/App Router와 GitHub Pages 버전이 같은 메인 React UI를 공유한다. 두 환경의 저장 방식과 인증 의미는 시연에서 구분한다.
- 실제 코드의 시각 토큰과 배치는 `app/spatial-live.css`, 메인 화면 구조는 `components/memory-app.tsx`, 읽기 패널은 `components/memories/spatial-panels.tsx`가 기준이다.

## 검증 기준

`390×844` 모바일과 `1440×900` 데스크톱에서 기본 지도, 장소 미리보기, 상세, 탐색, 검색, 기록 작성·수정·삭제를 Playwright로 확인한다. 스크린샷에서 화면 잘림·겹침·지도 빈 배경·가로 스크롤을 직접 검사하고 발견한 문제를 고친 뒤 같은 장면을 다시 캡처한다.
