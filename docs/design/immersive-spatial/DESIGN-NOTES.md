# Apple Spatial Memory 시안 검토

## 기존 화면과 구조 비교

현재 서비스의 기본 화면은 상단 고정 헤더와 왼쪽의 상시 노출 기억 목록, 오른쪽 지도 영역으로 나뉜다. 지도에 들어가기 전부터 여러 카드가 탐색의 중심이 된다. [현재 서비스 데스크톱 캡처](../../../test-results/screenshots/main-desktop-chromium.png)는 Playwright 실행 결과이며, `test-results`가 Git에서 제외되어 새 환경에는 자동 포함되지 않는다.

새 시안에서는 지도가 기본 화면 전체를 차지한다. 검색은 상단의 작은 부유형 입력, 이동은 하단의 작은 탐색 도크로 옮겼다. 기억 목록은 기본 화면에서 사라지고 **탐색**을 누를 때만 나타난다. 마커 선택은 작은 장소 미리보기를 열고, 이야기 선택은 사진과 긴 글 중심의 패널을 연다. 모바일에서는 미리보기와 상세가 손가락 접근 범위에 있는 바텀 시트로 전환된다.

| 사용자 동선 | 기존 서비스 | 새 시안 |
| --- | --- | --- |
| 첫 진입 | 목록과 지도를 동시에 읽음 | 장소가 표시된 전체 화면 지도를 탐색 |
| 마커 선택 | 기존 목록·지도 맥락과 함께 상세 흐름 진행 | 마커에 대한 한 편의 작은 미리보기만 등장 |
| 이야기 읽기 | 카드·시트 중심 | 큰 사진, 날짜, 본문이 중심인 편집형 패널 |
| 여러 기억 보기 | 기본 목록에 상시 노출 | 요청할 때만 탐색 패널 등장 |
| 모바일 | 기존 레이아웃을 모바일 시트로 재배치 | 지도 → 미리보기 → 확장 시트의 단계형 흐름 |

## 실제 서비스에 적용할 때

이 시안의 마커와 기억은 가상의 고정 자료다. 실제 서비스 연결 단계에서는 공개 지도 API의 viewport 질의, 장소 그룹, 작성자 권한, 정확·대략 위치의 응답 경계, 익명 작성자 정보 보호를 그대로 사용해야 한다. 지도 구현을 통합할 때는 기존 `components/memories/map.tsx`의 MapLibre lifecycle, 크기 보정, raster 호환 계층, 귀속 표시와 단일 마커 오버레이를 보존해야 한다. 검색, 필터, 내 기억, 기억 작성, 현재 위치, 뒤로가기, 사진 스크롤 등 기존 기능을 각각 새 탐색 흐름에 연결하고 회귀 검증이 필요하다.

시안 이미지와 본문은 가상의 시연 자료다. 상세 패널의 이미지가 실제 업로드 사진인 것처럼 오해하지 않도록 시안 안에 표시했다. 시안의 **내 기억**과 **기억 남기기**는 아직 API에 연결하지 않았다.
